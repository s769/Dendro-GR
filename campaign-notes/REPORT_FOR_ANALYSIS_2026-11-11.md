## 0. Goal and constraints

- Long-term goal: a large-scale **BBH inverse problem** (parameter inference from gravitational waveforms) using the Dendro-GR GPU **forward solver** (FP64 only) as the full-order model, with sensitivities (Jacobians, and ideally Hessians — the user is considering Riemannian-manifold MCMC and wants to decide between full adjoint capability and "RM-MCMC with up to second derivatives").
- Current phase (the user's instruction): make the forward solver and its sensitivities as fast as possible while keeping scientific accuracy ("if we get speedups while making scientific/systematic errors, that's not acceptable"). The user will think about the inference strategy (no lower-order surrogates; need high-fidelity guarantees) and come back; inversion phases (bilby-like injection–recovery, later a real LIGO event) are **on hold**. Eccentricity will later be an inferred parameter (first priority is non-eccentric).
- Hardware/process: TACC Horizon GB200 nodes (4 GPUs/node, Slurm partitions `debug`/`debug-shared`; user does not use SUs, early-user mode). Allocations are short and queue times are unpredictable; I request several and rely on checkpoint/restart.
- The user explicitly asked (this session): **use 64-bit indices where needed so overflow cannot happen** (done, see §4).

## 1. IMPORTANT: a correction to my own earlier numbers

For most of the night I measured accuracy with runs to **T=110** and compared psi4_22 at the **r=100 shell** (and called shell idx 5 "r=25" in some scripts). For the q=1, separation-8 binary the BHs are still at separation ~3.6 at T=110 (merger is at t~130–140 in the BH tracker; the psi4 peak at r=50 is at retarded time u≈145). At r=100 the retarded time at T=110 is only ~10 M, so those samples contain the **junk radiation / initial transient**, not the inspiral signal. Therefore the following earlier statements are **not** evidence about inspiral/merger waveform accuracy: "cap 13 error 0.007 rad", "cap 12 0.55 rad", "q=2 cap 13 0.175 rad", the CFL/remesh-interval accuracy table, and the "FD plateau through merger/ringdown" statements (the "merger at t≈84/102" I quoted was the junk wave passing the shell). They remain valid as indicators of how well the *transient and near-zone field* are resolved, and valid for cost and software-equivalence comparisons. Prominent correction notes are at the top of `campaign-notes/STATE_2026-11-11.md` and appended to `RESOLUTION_STUDY.md` and `OPEN_TASK_QUEUE.md`.

What replaced them: q=1, runs to T=260, extraction r=50, comparison on retarded time u=t−r with u≥60, tool `campaign-notes/analyze_inspiral.py` (see §3).

## 2. Environment / how things are run

- Solver: `~/Dendro-GR-build/BSSN_GR/bssnSolverCUDA` (CUDA, single-rank, `mpirun -np 1`). Typical env: `OMP_NUM_THREADS=8 DENDRO_RHS_PT_ASYNC=1 DENDRO_GW_SHELL_ONLY=1 DENDRO_BH_TRACK_FREQ=1`, `BSSN_ID_TYPE=0` (TwoPunctures; the solver only restores a pre-solved `<prefix>_tpid_sol.bin`, made by `tpid`), parameter file based on `BSSN_GR/pars/q1.par.toml` with overrides (`BSSN_MAXDEPTH`, `BSSN_BH{1,2}_MAX_LEV`, `BSSN_RK_TIME_END`, `BSSN_GW_EXTRACT_FREQ`, …). GW radii are 50,60,70,80,90,100 (columns r0..r5 in `dgr_GW_l2_m2.dat`).
- "cap N" = both BHs' max refinement level and `BSSN_MAXDEPTH` = N unless stated (the production pars use per-BH levels: q1 15/15, q2 16/15, q4 16/14, q8 17/14). `dt = 0.25·dx_min` (CFL 0.25), so higher cap ⇒ more steps.
- Scripts (all in `campaign-notes/`): `run_resstudy2.sh` ("name:cap:tol:gpu[:K=V;K=V]" variants, shared TwoPunctures solution in `resstudy2/tp`), `run_cfl.sh`, `run_rmf.sh`, `run_q_cfl.sh` (any q, per-BH levels via 5th/6th field), `run_fd_tp.sh` (production-ID FD fiducial + members, `REPLAY_ONLY=1`), `run_fd_hess.sh` (extra members for second derivatives), `run_ckpt_test.sh`, `resume_run.sh` (resume a checkpointed run dir), `run_nsys_c13.sh`, analysis: `analyze_inspiral.py`, `cmp_waveforms.py`, `analyze_hess_p2.py`, `analyze_hess_plateau.py`, `estimate_ecc.py`, `analyze_res.py`, `analyze_wave_fd_dgr.py`.
- **Launch pitfalls I hit:** (a) `pkill -f <pattern>` kills the calling shell if its own command line contains the pattern — use `pkill -x name` or PIDs from `/proc/<pid>/cwd`; (b) ssh to a freshly started node can fail ("pam_slurm_adopt") for ~20 s; (c) `(setsid nohup … &)` with `</dev/null` is required for detached launches; (d) per-node module trees can differ (one node lacked modules); (e) TOML: `BSSN_RK_TIME_END = 0.2.0` parse error when TEND has a decimal; use integers.

## 3. Results (with caveats)

### 3.1 Real inspiral convergence, q=1 (the key result)
Runs: `resstudy2/p12L_T260`, `p13L_T260`, `p14L_T260` (new binary, CFL 0.25, remesh 50, both BHs at the stated level), analysed with `analyze_inspiral.py REF VAR [ridx=0] [u0=60]`.
- cap 12: unphysical (BH separation → 0 before t=100).
- **cap 13 vs cap 14 (r=50 shell): dphase = −0.60 rad at u=100, −6.5 rad at the merger peak (u≈140), −7.2 rad after merger; amplitude error up to ~85%.** r=100 shell gives the same picture. Cap 13 inspirals too fast. Cap 13 is **not** adequate.
- **Whether cap 14 is converged is unknown.** The comparison needs cap 15 (and ideally 16) to T≥230. Production q1 par uses 15/15.
- p13L crashed at t=238 and p14L at t=256 (post-merger meshes crossed 65,535 elements; see §4.2). Their data up to the crash are valid.

### 3.2 Cost and speedups (software-only changes are equal to roundoff)
- With correct CPU binding: cap 13 q=1 T=110 ETS 784 s (original), 634 s with pinned pool + OpenMP intergrid transfer (−19%); output identical (|Δz| ~1e-16 at |z|~3e-5). cap 14 T=110 ~1860 s, cap 15 ~8600 s (T=110, one GPU, old binary).
- GPU time breakdown (nsys, cap 13, 1 GPU): main RHS 37%, unzip 25%, CAHD 18.5% (fused 11.8% + chi_rhs 3.6% + derivs 3.1%), boundary RHS 13%, axpy 2%, zip 2%. GPU kernel time is ~79 ms/step vs 116 ms/step wall: ~30% of wall was host work, dominated by remesh (per remesh: balance+partition 0.2–1.0 s, Mesh ctor 0.2–1.7 s, SendRecvCompute 0–0.9 s, intergrid transfer 0.4–1.3 s growing with mesh size).
- **Schedule knobs (junk-window evidence + q=2/q=4 cross-checks):** CFL must stay 0.25 (CFL 0.4 shifts the junk-window answer by 0.03–0.05 rad at q=2 and q=4; the apparent q=1 "improvement" with larger CFL is compensation between negative time error and positive spatial error). Remesh interval 80–100 steps had ~1e-4 rad effect at q=2 and −10…−13% wall (junk window only; not re-validated on the inspiral).

### 3.3 Sensitivities (finite differences)
- Harness `run_fd_tp.sh`: fiducial (records the mesh sequence via `DENDRO_MESH_RECORD`) + members that each solve their own TwoPunctures (bare mass of BH1 ±ε, warm-started from the base solution) and replay the fiducial mesh (`DENDRO_MESH_REPLAY`). Cap-13 members replay in ~14 min each, 4 concurrent per node (with correct binding).
- Production-ID FD derivative of psi4_22 w.r.t. m1: plateau between ε=1e-3 and 3e-3 of 6e-7 (early window), 2e-4 (t=62), 6e-4 (t=110). **Caveat: this is in the junk-dominated window (§1); it must be redone on the inspiral window at the converged resolution.**
- p=2 Hessian of psi4_22 w.r.t. (m1,m2) bare masses (`run_fd_hess.sh`, 15 members + fiducial, ε=3e-4/1e-3/3e-3): q=1 symmetry checks hold (J1=J2 to 1e-7…1e-10; H11=H22 to ≲1e-5 for t>50). Second differences have a noise floor ~1e-9|z| in the early window that grows ~1000× later; second-derivative accuracy ~1–3% at ε~1e-3 for the early window, tens of % later. Same junk-window caveat.
- Derivative-order analysis (in `OPEN_TASK_QUEUE.md`): a Fisher-metric RM sampler (SMMALA/RMHMC with G = JᵀC⁻¹J) needs the model Jacobian and its **first derivative** (i.e. model second derivatives), not third derivatives of the likelihood; so a full adjoint is not required for that route. p intrinsic parameters need 2p+1 solves for J and ≈2p²+1 for H via central FD; extrinsic parameters and total mass are analytic. For q=1 aligned only (J1,H11,H12) are independent (BH exchange symmetry).
- A tangent-linear/second-order tangent code (Tier 3.1 in older notes; standalone harnesses only, not integrated) is the noise-free alternative to FD for Hessians; not pursued further.

### 3.4 Mass-ratio dependence (junk window only — needs inspiral re-validation)
- Resolution that matters is per-BH points-per-mass. q=2 (junk window): per-BH levels (14,13) reproduced uniform level 14 to 1e-4 rad at −18% cost. q=4: uniform cap 14 is numerically wrong (BHs merge by t≈60); levels (15,12) crashed at ~70k elements (the §4.2 bug, not conclusively physics); (16,13) too slow to finish. Production pars q2/q4/q8 use (16,15)/(16,14)/(17,14).

### 3.5 Eccentricity preparation
- Existing `BSSN_GR/scripts/id.py` (Tichy–Marronetti PN low-eccentricity generator) gives positions/momenta; the tuned production par values differ smoothly in q from its output (ΔV_y ≈ 4e-4, ΔV_x ≈ 5e-4…1e-3 for q=1,2,4) — the repo has no eccentricity-reduction iteration. `estimate_ecc.py` gives residual e≈1e-4–4e-4 (q=1) and 5e-4–1e-3 (q=2) from BH tracks (crude). `R_orbit` (hard-coded 8 in wavelet-tolerance function 6) is now the parameter `BSSN_WAVELET_TOL_R_ORBIT` (default 8; default behaviour verified identical).

## 4. Bugs found and fixes (all in the repo / patches; build dir verified)

1. **CPU pinning (huge for wall times):** Open MPI/PRRTE bound every `mpirun -np 1` solver to one core; concurrent runs shared CPU 0 (~25% CPU each). Fix: `--bind-to none` in all single-rank launch scripts. All earlier wall-time numbers from concurrent single-rank runs (and "remesh dominates" conclusions) are suspect; accuracy numbers are not affected.
2. **Crash for meshes above 65,535 elements:** `MeshGPU::zip_cg/zip_dg` launched `dim3(m_zip_grid[0], m_zip_grid[1], dof)` with `m_zip_grid[1] = #blocks` (= #elements for the 1-element-per-block layout) on `gridDim.y` (limit 65,535) → `!! invalid arguments` (cudaErrorInvalidValue via `check_last_error`, device.h) and abort at the first step after a remesh to >65,535 elements. Fix: grid = (#blocks, max elems/block, dof) with kernels reading `blk` from `block_id_x`. Patch `patches/dendrolib/zip_grid_over65535.patch`. Verified: a 72,864-element run completes.
3. **64-bit indices (user request):** unzip/cg/stride sizes in kernels and launchers → `size_t` (`bssn_kernels.cuh`, `bssnCtxGPU.cu`, dendrolib `mesh_gpu.cuh`); `DVec`/`ts::Ctx` index type for the **CUDA targets only** → `unsigned long` (`bssnCtxGPU.cuh`; `ts.h` takes `DENDRO_DVEC_INDEX_64`, defined in `BSSN_GR/CMakeLists.txt` for CUDA executables; CPU solvers keep 32-bit); dendrolib `device.h` helper sizes → `size_t`. A first attempt segfaulted at 86,640 elements because ~15 RHS kernels still had `const DEVICE_UINT sz_per_dof = szpdof_uz;` (fixed). Patch `patches/dendrolib/index64.patch`. Verified: 86,836-element single-GPU run completes (T=1); small regression equals the previous binary to ~1.4e-17 abs at |z|~7e-7. The remaining single-GPU ceiling is GPU memory (~48 GB at 35k elements ⇒ ~125 GB at 86k; ~120–140k elements on a 186 GB GPU) and the superlinear host mesh costs (balance+partition 230 s at 152k elements). Remaining unsigned-int fields: block offsets within one variable (<2^32) — unchanged.
4. **`.cu` translation units had no OpenMP** (`CMAKE_CUDA_FLAGS` lacked `-Xcompiler -fopenmp`), so OpenMP pragmas in dendrolib headers were inert. Fixed in the top-level `CMakeLists.txt`; verified no output change with the intergrid fast path disabled.
5. **New optimizations:** pinned host-memory pool (`pinned_pool.patch`, `DENDRO_PINNED_POOL=0` disables; −6.5% ETS at cap 13) and OpenMP single-rank INJECTION intergrid transfer (`igt_omp.patch`, `DENDRO_IGT_OMP=0` disables; transfer 9.5 s → 2.35 s over 20 remeshes; the first version shared the RefElement scratch and corrupted the mesh — the thread-safe `getElementNodalValues(..., isDGVec, im1, im2)` overload is required). Apply order is in `patches/dendrolib/README.md`: `current_local_full`, `pinned_pool`, `igt_omp`, `zip_grid_over65535`, `index64`. **Risk:** dendrolib is a FetchContent dependency; the working tree in `~/Dendro-GR-build/_deps/dendrolib-src` carries all local edits, mirrored as patches; I did not test a clean reconfigure from patches alone.
6. **Checkpoint/restart works on the GPU solver:** kill at step 608, restore at checkpoint step 601 (`BSSN_RESTORE_SOLVER=1`), run to T=14: waveform differs by ≤1.3e-14 abs at |z| 7e-7 (2e-8 relative; not bitwise). Use `BSSN_CHECKPT_FREQ` ≈ 3000 steps (two rotating slots; ~815 MB per 10k elements). Caveat seen today: after the duplicate-launch episode (below) the restore picked an older slot than expected for p14N; the output `dat/` files may contain duplicate sample times — deduplicate by time before analysis.

Earlier-in-the-campaign items (from the previous context, summarized in the existing notes): GPU–CPU physics agreement ~1e-11 incl. remeshing; CAHD implemented on the GPU (contracted-Hamiltonian kernel, ~+7% overhead, `DENDRO_GPU_CAHD_*`), slow-start lapse, BH tracking option `DENDRO_BH_TRACK_FREQ`, parameter guard, init-grid mesh fix, frozen-mesh record/replay, Dendro vs SpEC/SpECTRE discussion (conclusion: keep Dendro-GR).
